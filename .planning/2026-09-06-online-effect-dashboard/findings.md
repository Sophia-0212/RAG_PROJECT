# Findings

## Known Context

- 现有前端是 `Prometheus/upload_mock` 下的静态 ES module SPA。
- 已有质量评测页，新页应作为第二个效果视图，而不覆盖离线评测。
- 模拟交互状态应仅保存在内存中，浏览器刷新后恢复默认数据。
- 要覆盖时间/版本趋势、多维拆分、A/B 对比、失败明细和告警/自动回滚。

## Pending Discovery

- 现有路由和侧边栏如何容纳第二页。
- 现有图表、筛选、抽屉/弹窗和表格组件的可复用程度。
- 现有 Mock API 的数据形状和状态更新方式。

## Architecture Findings

- `js/app.js` 通过 `pages` 映射注册 `render/mount` 页面模块，新页可遵循同一模式。
- `js/core/router.js` 使用 Hash Router，可新增 `/quality/online` 路由。
- 现有 `quality.js` 是发布前的离线评测与质量门禁，新页应与它并列，不要混合两类口径。
- 现有通用 UI 已覆盖 `pageHeader`、`panel`、`badge`、`segmented`、表格、抽屉、弹窗、开关和 toast。
- 现有项目没有图表依赖，趋势图宜使用语义化 HTML/CSS 或轻量 Canvas，避免为静态 Mock 引入大型依赖。
- `runEvaluation` 会在内存 store 中更新评测状态，新页的告警和阈值配置也可采用同一交互方式，刷新重置。

## Proposed Information Architecture

1. 页头筛选：日/周粒度、时间范围、当前版本、对比版本、租户、业务线、问题类型。
2. KPI 卡：非必要转人工率、答案采纳率、人工抽检正确率、高风险错答数；每张卡包含分子/分母、环比和口径。
3. 趋势区：按日/周显示三个核心指标，标出版本上线点和告警触发点。
4. 维度拆分：租户/业务线/问题类型切换，显示样本数、三个指标和版本差值，点击行过滤失败明细。
5. A/B 实验：基线组与候选组流量、样本数、绝对差值、置信状态与安全护栏。
6. 失败案例：会话、业务类型、失败原因、风险、实验组和版本；抽屉展示问题、答案、引用、用户动作和 trace。
7. 告警与自动回滚：阈值、统计窗口、最小样本、连续触发次数、动作、回滚目标、负责人和通知渠道。

## Metric Definitions

- 非必要转人工率 = 排除流程强制转人工后的转人工会话 / RAG 有效会话。越低越好。
- 答案采纳率 = 直接采纳或编辑后采纳的答案 / 可采纳答案。越高越好。
- 人工抽检正确率 = 质检判定正确的回答 / 已完成抽检的回答。越高越好。
- 高风险错答为硬护栏，不能用其他平均指标的改善抵消。

## Metric Model Correction

- 内部 CRM 智能问答不存在客服式“转人工”按钮；员工离开系统后去如流求助属于跨系统行为，当前页面不能直接观测或归因。
- 页面核心指标改为：自助解决率、未解决率、重复提问率、负反馈率、任务完成率、答案采纳率。
- 六项指标的适用会话、事件来源和分母不同，不能相加，也不能用一个指标替代另一个。
- ACL 泄漏、高风险错答、重复副作用继续作为发布硬护栏，而非业务效果 KPI。
- 只有未来增加显式“向专家求助”入口并打通 trace_id，才能可靠统计从问答到如流求助的转化。
- 当前六项 KPI 基线/候选值分别为：自助解决 70.8%/81.4%、未解决 21.9%/16.2%、重复提问 17.6%/11.3%、负反馈 9.8%/5.9%、任务完成 74.6%/85.2%、答案采纳 68.7%/76.5%。
- 候选组和基线组样本分别为 14,090 与 13,970，合计 28,060，匹配 9 月 1 日至 6 日约 4,600 次/日的项目规模。
- 失败案例只展示系统可观测事件；对于“未解决”案例，明确标注后续是否去如流求助不可观测。

## Business Scale Source of Truth

Source: `test/002_1. 模拟业务背景与结果总览.md`

- 18 个内部 workspace，640 注册用户，190 日活。
- RAG 日问答量 4,600，峰值 9 QPS；页面的日样本数应围绕该量级，不应制造百万级日会话。
- 126,400 份原始知识文档，186 万可检索 Chunk。
- 已定上线结果：线上有帮助率 68.7% -> 76.5%，人工转接率 21.9% -> 16.2%。
- 关联技术护栏：P95 4.85s -> 3.08s，Token 4,980 -> 3,760，审批恢复 99.61% -> 99.93%，重复副作用连续 5 个月为 0。
- 背景文档没有给出人工抽检正确率；页面中如果展示，必须明确它是为了交互演示而构造的运营数据。

## Reusable UI and Behavior

- `components/ui.js` 的 drawer/modal/action 支持异步回调、busy 状态和全局 toast，可直接用于失败案例、指标口径、实验操作和告警编辑。
- `mock-api.js` 的 `transact` 已实现只读 workspace 拦截与审计，新的实验/规则写操作应全部经过该函数。
- 现有设计 token 已包含蓝、绿、黄、红、青和紫等语义色，新页可使用蓝/绿/黄表达多指标，避免单一色相。
- 项目屏幕断点为 1180/920/760/560px，新建图表和实验布局需同步覆盖这些宽度。
