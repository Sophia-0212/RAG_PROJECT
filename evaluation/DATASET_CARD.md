# Ad CRM Golden Small V1 数据集卡

## 1. 定位

`ad-crm-golden-small-v1.0.0` 是一套可执行的小规模企业 RAG 黄金集，用于教学、回归框架验证和后续扩数的标注样板。它不包含百度或其他公司的内部数据，所有租户、角色、客户、政策、金额和错误码均为虚构。

高保真不等于冒充真实。这里的真实性来自统一的业务状态机、职责分工、权限边界、制度有效期、异常处置和可审计标签，而不是使用真实客户名称或内部机密。

## 2. 绑定资产

- 数据集：`evaluation/datasets/ad_crm_golden_small_v1.jsonl`
- 冻结知识快照：`evaluation/corpus/ad_crm_v1/`
- 机器清单：`evaluation/corpus/ad_crm_v1/manifest.json`
- 发布指纹：`evaluation/dataset_release.json`
- 标注规范：`evaluation/ANNOTATION_GUIDE.md`
- 预测契约：`evaluation/PREDICTION_CONTRACT.md`
- 回归器：`evaluation/runner.py`
- 发布门禁：`evaluation/release_gate.json`

## 3. 规模和覆盖

V1 共 64 条、91 个必须事实、58 个相关证据引用和 24 个禁止证据引用。

| 一级分桶 | 数量 | 主要失败模式 |
| --- | ---: | --- |
| single_fact | 8 | 简单制度和操作事实答错 |
| multi_turn | 8 | 指代、省略和前文实体解析错误 |
| terminology | 8 | 字段、缩写、状态码和错误码混淆 |
| multi_hop | 8 | 只找到一份材料，漏掉组合约束 |
| temporal_version | 8 | 使用了提问时点不生效的版本 |
| ambiguity_no_answer | 8 | 信息不足时猜测，或无资料时编造 |
| acl_negative | 8 | 跨租户、跨团队和受限文档泄漏 |
| prompt_injection | 8 | 用户或检索文档中的恶意指令劫持 |

数据切分为 development 16、locked 40、security 8。安全挑战集不用于日常调参；锁定集的答案标签也不应进入 Prompt、索引或训练数据。

## 4. 业务世界

样本覆盖线索治理、客户归属、广告主准入、销售预测、商务审批、广告投放、集成故障和数据安全。冻结语料同时包含当前制度、历史失效制度、受限资料和隔离的恶意上传材料，用来逼近生产中“文档都能被召回，但不是都能被回答或执行”的环境。

## 5. 标签

每条样本至少包含：身份主体、租户、提问时点、历史对话、预期动作、预期路由、相关证据的 source/version/section、相关性等级、必须事实、可自动匹配表达、禁止证据、禁止事实、风险级别、切分和标注审计信息。

`match_any` 只用于确定性的事实覆盖冒烟，不代表完整语义等价判定。企业正式评测仍应增加 claim 拆分、人工复核或经过校准的 LLM Judge。

## 6. 适用与不适用

适合：验证评测工程、比较检索或 Prompt 版本、演练权限/版本硬门禁、学习失败分析。

不适合：声称生产模型已达到某个质量水平、代表真实员工问题分布、训练基础模型、估算线上业务收益。64 条的置信区间较宽，不能替代脱敏线上日志和真实业务专家标注。

## 7. 已知偏差

- 由规则驱动的人工合成样本比真实员工问题更完整、更干净。
- 商务和安全高风险问题被主动过采样，不代表线上自然占比。
- 当前确定性生成评测只检查事实短语覆盖，尚不测表达质量、完整 claim groundedness 和隐含矛盾。
- Runner 当前消费离线预测文件；生产 API 回放适配器和 baseline/candidate 显著性比较仍是后续能力。

## 8. 版本治理

任何问题、答案事实、证据版本、切分或标注结论改变，都必须提升数据集版本并重新计算发布指纹。线上失败样本只有完成脱敏、去重、证据绑定、双人复核和仲裁后才能进入下一版本。
