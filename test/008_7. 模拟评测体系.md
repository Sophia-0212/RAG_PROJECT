## 7. 模拟评测体系

### 7.1 Golden Set

仓库当前可核验的教学 V1 为 64 条高保真虚构样本，八个一级分桶各 8 条；development 16、locked 40、security 8。它绑定冻结知识快照、Schema、标注规范、Runner 和门禁，作为扩数样板，而不是冒充真实生产数据。

模拟项目的后续目标是扩展到 2,400 条，经业务专家双人标注与仲裁：

| 分桶 | 数量 |
| --- | --- |
| 单轮事实 | 620 |
| 多轮指代/省略 | 360 |
| 字段名/错误码/缩写 | 310 |
| 多跳组合 | 260 |
| 版本/时间冲突 | 210 |
| 无答案与歧义 | 260 |
| 权限负例 | 240 |
| Prompt injection/恶意输入 | 140 |

目标规模中 600 条用于开发和阈值选择，1,800 条锁定测试。按 source document 和问题模板分组切分，避免相邻 chunk 或同义问法跨集合。权限与安全用例必须 100% 通过才允许发布。该 2,400/1,800 规模尚未在仓库落地，不应当作当前实现证据。

### 7.2 模拟消融实验目标

下表属于虚拟项目推演数据，不是当前 64 条资产上的实测结果。获得候选系统逐条预测并由 Runner 产出报告后，才能替换为可证明指标。

固定同一生成模型、Prompt、知识快照和测试集：

| 方案 | Recall@10 | nDCG@10 | 正确率 | Groundedness | P95 | Token/请求 |
| --- | --- | --- | --- | --- | --- | --- |
| Dense only | 71.3% | 60.4% | 66.4% | 82.8% | 2.18s | 3,050 |
| Dense + Sparse RRF | 82.4% | 70.8% | 71.6% | 85.2% | 2.28s | 3,070 |
| + Cross-Encoder Rerank | 85.1% | 77.2% | 75.4% | 88.3% | 2.51s | 3,200 |
| + 按需自纠错 | 85.1% | 77.2% | 80.1% | 93.6% | 3.08s | 3,760 |
| 无条件两轮校验 | 85.4% | 77.1% | 80.5% | 93.8% | 4.85s | 4,980 |

结论：

- 混合检索主要改善 lexical-heavy 与多轮独立化后的召回。
- reranker 主要改善产品线、组织和版本错配。
- 自纠错不改变第一轮 Recall@10，而是提高证据充分性和生成忠实度。
- 按需自纠错比无条件两轮少 1.77 秒 P95、少 24.5% Token，只损失 0.4 个百分点正确率，因此选择前者。

### 7.5 共享状态发布门禁

算法 Golden Set 之外，RAG Service 发布还必须通过两层状态测试：离线单元测试验证锁、限流、错误码、配置和部署清单；真实 PostgreSQL/Redis 隔离集成测试验证两个独立运行时共享 checkpoint/会话、跨客户端 lease/配额和 SQLite 迁移幂等。目标环境还要补连接耗尽、Redis failover、PostgreSQL failover、Pod 滚动和长时间浸泡测试。

自动恢复门禁再增加四个确定性 crash window：首个 checkpoint 前、pending 节点、图完成未 finalize、finalize 后响应丢失。必须证明已 checkpoint 节点不重放、失败节点允许 at-least-once、旧 token 被 fencing、同一 request_id 只有一个 turn；另测 IAM 撤权和 graph_version 不兼容时 fail closed。
