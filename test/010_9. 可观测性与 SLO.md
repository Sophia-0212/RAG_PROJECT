## 9. 可观测性与 SLO

### 9.1 统一 Trace

每次运行关联 request_id、workflow_run_id、conversation_id、approval_task_id 和 execution_id。Trace 保存：

- 脱敏后的原问题、standalone query、实体 diff 和路由。
- tenant、ACL filter 摘要、policy version。
- dense/sparse 候选 ID、排名、RRF 和 rerank 变化。
- 进入模型的 citation ID、文档版本和 Token 数。
- 模型、Prompt、graph、index、embedding 和 reranker 版本。
- evaluator label、reason code、循环次数和降级原因。
- action hash、审批决策和执行结果摘要。

不保存完整客户隐私、密钥或无权限正文。生产问题回放需要受控审批和脱敏快照。

### 9.3 状态面可观测性

- readiness 分别暴露 checkpoint、conversation、coordination、identity，避免一个总布尔值掩盖故障依赖。
- `rag_dependency_ready{dependency}` 记录各依赖就绪状态。
- `rag_coordination_events_total{action,outcome}` 记录 lease 获取、续租、释放及协调失败，标签保持低基数。
- 平台同时采集 PostgreSQL 池等待/事务延迟/连接使用率，以及 Redis 延迟/切换/淘汰/内存；这些基础设施指标不由应用伪造。
- `rag_run_events_total{action,outcome}` 记录 submit/claim/finalize/recovery 的低基数结果；`rag_recovery_backlog` 与 oldest seconds 用于积压告警。运行事件只带 request_id 和哈希身份，不记录 question、payload 或 result。

上述 99.9% 和 3.5 秒仍是模拟 SLO；代码中的超时、并发、池大小和 HPA 是保护性默认值，不等同于已达成 SLO。

RAG 自动恢复成功率必须单独定义分母：进入 `RETRYABLE` 且恢复窗口内符合版本/权限条件的运行。IAM 已撤权、版本不兼容和客户端显式取消应分桶，不得混入依赖瞬时失败来美化指标。
