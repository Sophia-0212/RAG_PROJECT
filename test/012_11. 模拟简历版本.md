## 11. 模拟简历版本

> 警告：下面仅展示“完整项目数据具备时”的写法，不是可以直接冒用的真实简历。

**百度在线网络技术（北京）有限公司｜CRM 业务组 后端研发 / AI Agent 工程师｜2024.10 - 至今**

- 负责 ONECRM 客户档案聚合查询与变更链路治理，支撑 3,100 万客户档案、峰值 1,600 读 QPS；通过缓存分层、批量聚合与慢查询治理将核心查询 P95 从 186ms 降至 94ms，并以事务 outbox 保证搜索与标签链路的可观测最终一致。
- 负责基于 Dify 的 CRM Agent 工作流平台企业化改造，完成 workspace/app/workflow/knowledge/tool 多层权限适配，并设计可暂停、可恢复、可超时、可审计的 HITL 审批节点；平台日运行 1.18 万次，审批恢复成功率 99.93%，通过 action hash、CAS 与业务 execution_id 消除已知重复副作用路径。
- 核心参与 LangGraph RAG 引擎建设，基于 Milvus 实现 dense+sparse、weighted RRF 与 cross-encoder 重排，构建检索相关性、证据充分性与 claim groundedness 的有界自纠错图；在 1,800 条锁定测试集上将 Recall@10 从 71.3% 提升至 85.1%、端到端正确率从 66.4% 提升至 80.1%，按需自纠错将 P95 从无条件双轮的 4.85 秒降至 3.08 秒。
- 设计 RAG Service 的 SQLite 本地/PostgreSQL 生产双后端与 Redis 跨副本协调，增加请求运行账本、租约 fencing、`invoke(None)` 续跑、IAM 再鉴权及幂等终态提交，形成 3 API Pod + 2 恢复 Worker 的 Kubernetes 基线；仓库仅证明工程与离线语义，真实恢复率、HA、容量与 SLO 必须以实际环境证据替换。
- 建立 Prompt/模型/索引版本化与全链路 trace，推动权限负例、故障注入和 RAG 消融进入发布门禁；线上 6 周实验有帮助率提升 7.8 个百分点，人工转接率下降 5.7 个百分点。
