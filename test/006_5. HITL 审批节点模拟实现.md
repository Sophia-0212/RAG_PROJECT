## 5. HITL 审批节点模拟实现

### 5.1 使用场景

| 风险等级 | 示例 | 默认处理 |
| --- | --- | --- |
| L0 只读公开 | 查询通用 SOP | 自动执行 |
| L1 只读受限 | 查询客户归属与联系人 | 授权后执行并审计 |
| L2 可逆写 | 修改客户标签、创建跟进任务 | 高金额/批量时审批 |
| L3 高风险写 | 客户归属转移、批量触达、敏感导出 | 强制审批 |
| L4 禁止 | 删除审计、绕过权限、任意 SQL | 不暴露为 Tool |

### 5.2 状态机

```
CREATED -> RUNNING -> WAITING_APPROVAL
                         | approve
                         v
                     APPROVED -> RESUMING -> SUCCEEDED
                         |          |
                         |          +-> FAILED_RETRYABLE -> RESUMING
                         |          +-> FAILED_TERMINAL
                         +-> REJECTED

WAITING_APPROVAL -> EXPIRED / CANCELLED
```

状态不变量：

- task_id + task_version 只能产生一次有效决策。
- APPROVED 仅代表风险确认，不代表 CRM 动作成功。
- normalized_action_hash 变化后旧审批失效。
- 终态不能被普通回调重新打开。
- 恢复前重新鉴权，并固定原 workflow_version 与 node_version。

### 5.3 核心数据

```
approval_task:
  task_id, tenant_id, workflow_run_id, node_id
  task_version, status, requester, approver_rule
  normalized_action, action_hash, risk_level
  workflow_version, node_version
  expires_at, created_at, decided_at

workflow_checkpoint:
  run_id, node_id, state_blob_ref, state_schema_version
  workflow_version, attempt, created_at

execution_record:
  execution_id, action_hash, target_resource
  status, result_digest, error_category
```

### 5.4 暂停与恢复时序

1. Tool Gateway 将模型输出规范化为 action proposal。
2. Policy Adapter 返回 require_approval 和审批规则。
3. 同一事务写 checkpoint、approval_task 和 notification_outbox。
4. worker 返回 PAUSED，不保持线程或连接。
5. 任务中心发送卡片，展示目标、参数、影响范围、证据和有效期。
6. 审批回调使用 task_id + version 做 CAS。
7. Resume worker 抢占 30 秒 lease，校验 action hash、版本和权限。
8. 调 ONECRM 时携带 execution_id。
9. ONECRM 在业务事务内记录 execution_id 与结果，重复请求返回历史结果。
10. 审计链保存提议、策略、审批与执行摘要。
