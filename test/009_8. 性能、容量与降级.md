## 8. 性能、容量与降级

### 8.1 延迟预算

| 阶段 | P50 | P95 |
| --- | --- | --- |
| 身份/权限 | 8ms | 18ms |
| Query rewrite | 110ms | 240ms |
| Dense + Sparse 并行召回 | 42ms | 91ms |
| 融合与去重 | 6ms | 16ms |
| Rerank | 82ms | 170ms |
| 生成完整答案 | 1.12s | 2.05s |
| Claim 校验 | 170ms | 420ms |
| 平台与网络开销 | 95ms | 210ms |
| 端到端 | 1.76s | 3.08s |

P95 不能由各阶段 P95 直接相加，因为请求分布和并行阶段不同；端到端以 trace 实测。

### 8.2 容量保护

- workspace 级并发、QPS、日 Token 和单流程节点数配额。
- 单运行最大 60 个节点、最长 15 分钟；审批等待不计执行时长。
- RAG 最大 2 次检索重试、1 次生成重试、6 秒 deadline。
- 队列按租户加权公平，单租户最多使用 30% worker。
- 模型网关使用 200ms/500ms/1s 指数退避加 jitter，总重试不超过一次。
- 高错误率时熔断模型或 reranker，避免重试风暴。

### 8.3 降级矩阵

| 故障 | 降级 |
| --- | --- |
| Rewrite 模型超时 | 原问题 + 最近已确认实体 |
| Dense 服务失败 | Sparse only |
| Sparse 服务失败 | Dense only |
| Reranker 超时 | RRF 排名 |
| 生成主模型失败 | 经过 schema 回归的备用模型；高风险问题拒答 |
| Evaluator 超时 | 低风险带提示返回，高风险拒答/转人工 |
| Milvus 不可用 | 已验证 FAQ 缓存，否则明确不可用 |
| ACL 服务异常 | 高敏检索与动作 fail closed |
| 审批中心异常 | 已持久化任务等待恢复，不绕过审批 |
