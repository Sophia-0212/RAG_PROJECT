# LLM Judge 自我偏好偏差与三层防御

面试考点：用 LLM 给 RAG 生成的答案打分（判断 grounded/not_grounded、事实覆盖等）时，如果评判模型和生成答案的模型同源（同厂商、同系列，甚至同一个模型），会产生"自我偏好偏差"（self-preference bias）——这是 LLM-as-judge 方法本身公认的固有局限，不是某个项目的个别失误。能不能讲清楚"风险本身是行业共识"和"某个项目具体犯没犯这个错"是两件不同的事，是区分候选人是否只会背概念、还是真正理解工程取舍的分界线。

## 简答版

同一个模型（或同系列模型）既生成答案又给答案打分，评判者对自己熟悉的表达风格、措辞习惯、论证方式会有天然偏好——不是故意作弊，是评判标准跟生成偏好本身高度重合，导致打分偏高、不可信。这个现象叫 self-preference bias，是学术界和工业界反复验证过的已知风险，不是个别企业的失误。

企业级做法不是假装这个风险不存在，是分三层去控制它的影响面：

1. **架构层面**：生成模型和评判模型尽量选不同厂商/不同系列，降低同源偏好。
2. **监控层面**：定期抽样人工复核 AI 打的分，计算"AI 判断和人工判断的一致率"，一致率异常下滑就说明这个 Judge 该调整或换掉了。
3. **流程层面**：权限判断、价格承诺、账户暂停这类高损失结论，永远不让纯 AI 打分说了算，必须走人工确认，不管 AI Judge 打分多高都不能替代人工签字。

### 具体场景演示（面试官追问"怎么发生的"时展开）

```
候选 RAG 系统的生成模型 = 某厂商 A 系列模型
LLM Judge（负责判断 grounded/事实覆盖） 也用 = 厂商 A 系列的另一个版本

候选答案的措辞风格、论证方式，是模型 A 系列自己熟悉的表达习惯
Judge 判断"这个答案是否 grounded"时，同系列模型更容易"认同"这种表达方式，
给出偏高的评分——不是故意放水，是评判标准跟生成偏好高度重合
```

这不是假设性的担忧，是已经被专门讨论过的具体风险场景：LLM Judge 对自己同系列模型答案给出的未经校准评分，正是"哪些内容不能完全交给 AI"这类清单里被明确点名排除在"AI 可以自主决定"范围之外的一类判断。

## 深答版——"共识"和"犯错"不是一个问题，拆开讲才有说服力

如果面试官追问"你们这个项目是不是也用同源模型做过评判"，不要用"是"或"不是"直接回答，按下面的结构拆开讲，展示的是工程判断能力而不是背概念能力。

**第一层：风险本身是共识，不是某个项目的错**

self-preference bias 是这类 LLM-as-judge 方法本身固有的局限，任何用 LLM 打分的团队都要面对这个问题，不存在"完全避免"这种说法，只有"控制影响面到什么程度"。

**第二层：具体项目有没有犯错，取决于有没有配套缓解措施，不取决于是否用了同源模型**

三种真实场景，性质完全不同：

```
场景 A（合理取舍）：知道风险，但资源有限只能用同源模型，
       配了抽样人工校准兜底，定期监控一致率有没有异常
       → 这是在约束条件下做的负责任选择，不是"错误"

场景 B（真正的问题）：不知道这个风险，直接拿生成答案的同一个模型当 Judge，
       从没做过抽样校准，高风险判断也让 AI 自己说了算
       → 问题不在"用了同源模型"，在"没有意识到风险、没有配套缓解"

场景 C（主动取舍）：知道风险，但业务规模小、风险容忍度高（内部工具，不涉及资损/合规），
       主动选择接受这个风险，不投入模型分离/人工校准的额外成本
       → 也是合理取舍，前提是"主动决策"而不是"没想到"
```

**关键判断（体现层次感）**：区分候选人水平的不是"知不知道 self-preference bias 这个词"，是能不能讲清楚"共识级风险"和"具体项目的工程决策质量"是两个维度——一个是关于方法论本身的认知，一个是关于团队有没有把认知转化为分层防御机制的执行力。

## 30 秒精简版（面试时间紧张时用）

> "同源模型做生成和评判存在自我偏好偏差，这是 LLM-as-judge 方法本身公认的局限，不是哪个项目的个别失误。关键不在于是否完全避免了同源，在于有没有配套的分层缓解——尽量让生成和评判模型来自不同厂商，做不到完全隔离时定期抽样人工核对一致率，最关键的是权限、价格这类高损失判断从设计上就不给 AI Judge 最终决定权，人工确认是硬性关卡，不因为 AI 打分高就绕过去。"

这个版本的价值在于不把自己包装成"完全避开了这个坑"（这种说法反而暴露对风险复杂性理解不深），是展示"风险存在→无法 100% 消除→但可以分层控制影响面"这种更成熟的工程思维。

## 面试官在这类问题里通常评估什么

1. **是否理解"共识风险"和"具体犯错"是两个维度**——很多候选人会把这两者混成一个问题，要么过度辩护（"我们完全没有这个问题"），要么过度自责（"这是我们的失误"），都不如拆开讲显得成熟
2. **是否能讲出分层防御，而不是单点措施**——只说"我们做了人工审核"远不如讲清楚架构层（模型分离）、监控层（一致率校准）、流程层（高风险人工兜底）三层分别解决什么问题
3. **是否能识别哪些判断绝对不能让纯 AI 说了算**——权限、价格、账户操作这类高损失结论，即使 AI Judge 打分很高也不能替代人工签字，这个边界感是核心考点
4. **是否会用具体机制而不是口号回答**——"抽样审计 AI 与人工一致性"这种具体、可执行、可监控的机制，比"我们很重视评测质量"这类空话有说服力得多
